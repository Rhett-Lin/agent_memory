# Round 5：用户提出「不求 P 真值，改为用冻结判据*定义* P 的状态」——可行性裁决

用户的原话：**"我们不必获得 P 的真值，可以设计一个机制／准则来定义：如果满足了什么条件，
那么我们认为现在 P 处于什么状态。"**

我认为这不是前四轮任何一条的重复，请裁决。

## 1. 我对这个提法的形式化（请先判定我有没有把它抬高）

区别在于**分类器 vs 认证器**：

- **分类器**必须给每个 pair 一个标签 → 未见失配机制上只能猜 → P̂ v1 LOAO 0.590 就是这个的实测；
- **认证器**只在**充分条件成立**时发声，条件不成立时输出 `unresolved` → 未见机制落入弃权而非误判。

即：不再把 P 当待估计的隐藏真值，而是定义一个**构成性（constitutive）判据** `P̃`：

```
P̃(x,m) = CERTIFIED_CONFLICT   若 ∃ 一个被见证的、任务必需成分上的矛盾
       = CERTIFIED_MATCH      若 所有任务必需成分均可比且一致
       = UNRESOLVED           否则
```

这与你 R1 给的 `I_P(O)` 三值结构同形，但用户的版本多了一个可操作的承诺：
**判据由我们选定并冻结，成功标准是"触发时是否可靠 + 触发多少"，而不是 AUC。**

**裁决点 1**：这是合法的测量学转向（如"程序等价"不可判定但"在测试集 T 上等价"可判定；
如类型系统的 well-typed 是故意保守的充分条件），还是只是给一个失败的分类器换名字？
若合法，**使它非循环、非换名的最小条件是什么**？（我的候选答案：判据必须先冻结+hash、
必须只用部署可得的观测、必须报告 coverage 而不能只报 precision、必须在独立选择的未见机制上再测一次。）

## 2. 我的具体实例化：**非对称认证器——只认证 CONFLICT，永不认证 MATCH**

理由（请批判）：

- 认证 MATCH 需要**完整性证书**（所有任务必需成分都被比较过），而完整性正是我们最没有的东西：
  扩编审计实测假 ABSENT **19.6% 槽级 / P4 29.6%**、必需角色槽 41.4% present / 39.0% unknown、
  branch 节点仅 52.8%。
- 认证 CONFLICT 只需要**一个被见证的分歧**——局部性质，不需要完整性。
- 而部署侧真正要的就是**抓住有害的 A01**，不是证明 A11 好。

对应的准入规则：`admit ⟺ ¬CERTIFIED_CONFLICT ∧ 风险门通过`。

**裁决点 2**：这个非对称设计是否比对称三值更强？有没有我没看到的不健全性？

## 3. 关键：现有审计**没有**回答这个问题（请核对我的读法）

`pilot/peval/phi_d/audit_expanded/AUDIT_EXPANDED.md` 的门是
**overall all-rows 一致 ≥0.90，且"missing 计为不一致"**，即**全行**口径。
它的判词是"无一字段保留硬否决资格"，但同一文件同时判定：
**`pred_op` present-only 0.908（297/327）→ 符合 positive-only veto / soft evidence 资格**。

而认证器的真正 estimand 是**pair 级、条件于触发**的量：

```
VetoPrec  = P(P*=0 | 规则触发 CONFLICT)
VetoCov   = P(规则触发 CONFLICT | P*=0)        ← 这才是安全收益
FalseVeto = P(规则触发 CONFLICT | P*=1)        ← 尤其在 A10 上（分解式 judge 在这里误杀 85%）
```

**这三个量从未被测量过**（S2 比较器从未建成）。

**裁决点 3**：我的读法对吗——扩编审计**否定的是全行硬否决，没有否定条件触发式认证**？
若对，这是否意味着 lane A（比较器基线）应该从"≤1 天基线一次跑"升级为本轮主线？

## 4. 一个我预测的结构性结果，请判定它是否成立且是否值得报告

四种 near-miss 里：

| 机制 | 性质 | 文本可认证性预测 |
|---|---|---|
| P1 conditional_write：比较符翻转 | **存在性**（两侧都写出了 op） | 可能可认证 |
| P2 two_row_transfer：方向反转 | **存在性**（source/destination 角色） | 可能可认证 |
| P3 aggregate_gate：门控子集错误 | **存在性**（"none open" vs "at least one done"） | 可能可认证 |
| P4 delete_after_capture：**跳过 archive** | **缺失性** | **结构上不可认证** |

因为认证缺失需要区分 ABSENT（真的没有该步骤）与 UNKNOWN（抽取没看到），
而实测假 ABSENT 19.6%（P4 29.6%）正好摧毁这个区分。

**裁决点 4**：「缺失型 near-miss 在文本上结构性不可认证，只能靠执行或接口证据」——
这是不是一个可写进论文的真结论？需要什么统计支持？

## 5. 成功指标该用哪个（我倾向后者）

- (a) 对 P 的 precision / coverage；
- (b) **策略价值 vs oracle-P 天花板**——我们有完整析因，可以**精确计算**任何 gate 的 policy value。
  已注册事实：`GATE_EVAL.json` 上 P̂-gate@0.6 = **+8.59pp** vs never-admit，而 **oracle-P 上限 = +8.13pp**
  （7B，640 实例，0 丢弃；差值属抽样噪声，CI 重叠）。

(b) 的含义很强：**在域内，一个"够用的判据"在策略价值上已经追平 oracle**。
这说明部署要的不是复原 P，而是一个策略价值接近 oracle 的闸。

**裁决点 5**：主指标应设为 (b) 吗？若是，冻结口径怎么写（family-cluster bootstrap？
非劣 margin？必须同时报 A01 接受率与 A10 保留率？）。注意 R2 已裁 A01 accept ≤0.10 / A11 retain ≥0.50
为准入门，这里是否需要新增 A10 保留下限（防 compare-and-kill 跨域等价）？
