# MAPPING.md — H-C minimal gate: representation system ↔ published method

Frozen by `GATE_PROTOCOL.md` Part II §9 ("系统（write-path 表示层…）") and
`SELECTED_HYPOTHESIS.md` ("'忠实复刻'只保证表示层…留给审稿人可查").
This table is the honest mapping reviewers can check.  **Scope honesty:** these
systems are **write-path representation layers** run inside one shared harness
(same prompts, tools, budgets, fixed injection, no retriever).  They are **not**
full online pipelines of the cited works — no retrieval stage, no reflection
loop at test time, no training, no memory-store writes during the grid.

| system | card content injected as `[MEMORY]` | stands for (write-path representation of) | construction (this repo) |
|---|---|---|---|
| `raw` | Verbatim transcript dump of ONE successful source episode: `step k: {"tool":…}` + `<tool_result>…</tool_result>` lines, hard-truncated to ≤300 Qwen2.5-1.5B tokens (window 200–300; shorter transcripts kept, flagged `below_window`). | **Reflexion** (Shinn et al. 2023) / **ExpeL** (Zhao et al. 2024) style *full-trajectory replay*: the stored experience is the raw episodic trace (tool calls + observations), unsummarized, replayed as context. | `build_raw_cards.py`: qwen7b no-memory rollout on the card's exact source task (recovered from sealed generator records), 1 seed, ≤2 retries, success-only; failures use `program_dsl.run_oracle_plan` trajectory marked `oracle_fallback=true`. |
| `summary` | LLM-compressed procedure summary (≤300 tokens) of the *same* full untruncated trajectory used for the `raw` card. Qwen2.5-7B-Instruct, temperature 0, frozen prompt (stored in `build_summary_cards.py:SUMMARY_PROMPT`, sha recorded per row). | **Generic summary-memory** write path (the summarization step shared by many agent-memory systems, e.g. the insight/experience abstraction of ExpeL-style pipelines and typical "reflect-and-summarize into memory" agents): the stored experience is a model-written natural-language summary of the episode. | `build_summary_cards.py`: prompt contains ONLY task instruction + transcript (pre-registered anti-leakage, §12 — no family/cell/P/S labels). |
| `procedural` | Pilot procedural card (goal / preconditions / ordered steps / postconditions / failure guards), 6 style templates Latin-squared, padded to the 200–300-token window. | **Memp** / **AWM**-style *procedural skill memory*: the stored experience is an abstracted executable procedure (schema-like steps distilled from episodes), not the raw trace. | Pilot asset, generated by `generate_families.py` from the sealed program roles; rollouts reused verbatim from `outputs/agent_memory/pilot/rollouts_qwen7b_shard*-of-*.jsonl` (pre-registered reuse, §9). |

Shared controls across all three systems:

- same 40 families × 4 target siblings × 6 cells × 4 seeds × qwen7b grid;
- cell **N**: no memory injected; cell **Q**: the SAME pilot sham card text in
  all three systems (task-irrelevant filler procedure);
- identical harness config (`configs/pilot_7b.yaml`), parsing, terminal
  predicates, budgets (12 steps), token-meter code path, config-hash and
  commit recording per rollout;
- per-cell Latin-square style balancing applies to `procedural` only;
  `raw`/`summary` have no style template (format fixed by construction).

What this mapping does **not** claim (registered caveats):

1. Not an implementation of the named papers' full pipelines (no reflection
   loops, retrievers, verifiers, or online memory updates) — only the
   write-path representation layer is held faithful to the published form.
2. `raw` cards are truncated at the 300-token window ceiling, not at the
   papers' original context budgets; card-length SMD across systems is
   measured and reported as a potential confound (§10).
3. `summary` is generated by the same backbone family as the agent
   (Qwen2.5-7B) at temperature 0 — a deliberate, frozen choice; summary
   quality is gated by the pre-registered 10-card manual audit (§12,
   kill condition >30% defective).
