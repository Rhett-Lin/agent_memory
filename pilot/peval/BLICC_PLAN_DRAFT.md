## 0. 问题重定义（裁决产物，取代原问题表述）

**原目标（已被裁 NO_GO）**：继续提高 text-only P̂ 的 AUC。

**新 estimand**：P 不是部署可观测量，而是**部分识别对象**。设部署可观察信息
`O = (x_text, m_text, tool schema, policy/version provenance, probe results)`，定义与 O 相容的程序集合
`Γ_x(O), Γ_m(O)`，识别集合

```
I_P(O) = { 1[z_x ≡ z_m] : z_x ∈ Γ_x(O), z_m ∈ Γ_m(O) }
```

只有三种结果：`{1}` certified match / `{0}` certified conflict / `{0,1}` unresolved（必须弃权或获取新信息）。

**交付物不是一个分类器，是一条曲线**：每往写入侧多存一件东西，certified 覆盖率涨多少、精度是否守住。

```
Cert(A)     = Pr[|I_P(O_A)| = 1]                  证书覆盖率
Validity(A) = Pr[P* ∈ I_P(O_A)]                   识别集合是否真的含真值（必须 = 1）
Prec(A)     = Pr[P̂ = P* | |I_P| = 1]              单点判定精度
Cost(A)     = (bytes, write latency, probe calls, rollback need)
```

且必须**分两层报告**，否则"接口信息不足"与"parser 失败"会混在一起：

1. **Information ceiling**：假设接口字段被无误读取时理论上能识别多少；
2. **Achieved certifier**：实际 canonicalizer/checker 达成多少。

## 1. 合法接口梯度与非法来源（本方案的核心纪律）

| 点 | 内容 | 本 benchmark 合法性 |
|---|---|---|
| **T** | 文本（instruction + memory text） | 合法 |
| **T+S** | + tool / table schema | 合法 |
| **T+S+V** | + policy value / version / provenance | 合法 |
| ~~+X~~ | canonical executable artifact | **本轮删除**（见下） |
| ~~+W~~ | pair-discriminating witness | **本轮删除**（除非来源合法） |

### 1.1 X 的 oracle laundering 禁令（第三轮裁决，已逐条核实代码）

| 候选来源 | 裁决 | 核实依据 |
|---|---|---|
| generator 的 `z` / roles dict | **非法** | 就是 sealed oracle 换个名字 |
| procedural card | **非法** | `pilot/systems/MAPPING.md:15`："generated by `generate_families.py` from the sealed program roles" |
| `oracle_trajectory()` | **非法** | `build_raw_cards.py:156`：`ARCHETYPES[fam_row["archetype"]](task_row["program_params"])` + `run_oracle_plan(..., task_row["oracle_plan"])` |
| 真实 agent 轨迹 | **可作输入证据** | `harness.py:272-292` 逐步记录实际解析动作与 tool result |
| 由轨迹事后推得的 IR | 只能叫 **trace-consistent IR** | 未经证明不得称"实际执行的程序" |

正确形式：`Γ_k = { σ(z) : z ∈ H_DSL, z 与 k 条真实轨迹 + schema + provenance 相容 }`，
**仅当 `|Γ_k| = 1` 才可报 certified signature，否则 abstain。**

### 1.2 X 必须拆 X1 / X2，且现有数据不够做 X2

| 点 | 定义 | 可做的声明 |
|---|---|---|
| **X1** | 单条真实轨迹（k=1） | 只能排除与已观察动作冲突的程序；**不能**认证参数、未走分支、偏序 |
| **X2** | 多个**不同实例**的真实轨迹 + 必要干预 | 版本空间成为单点时可认证 bounded-DSL signature |

X2 的最低覆盖证书（冻结）：k ≥ 6 个不同初始状态/绑定的实例；每个拟参数化角色 ≥3 个不同绑定；
每个二值 guard 两侧各 ≥2 次；每个门控元素至少各一次 eligible / ineligible；方向角色 ≥3 个非对称绑定；
每对可能独立的操作必须观察两种顺序或有 fault/schedule 干预，否则 dependency 保持 UNKNOWN。
预注册预算点 k ∈ {1,2,4,6,8,12}，到 12 仍非单点即 abstain，不再追加执行。

**对现有 640 条来源的直接裁决**：

- 188/640 是 oracle reconstruction → 必须从 X1/X2 排除；
- 剩余 452 条虽是真实 rollout，但 `build_raw_cards.py:19-21` 明写"4 张卡共享同一 source task，
  只是 decode seed 不同"→ **同一初始任务的不同 seed / retry 不算不同实例**，不构成多实例泛化；
- source-task join 依赖 sealed family/cell mapping（`build_raw_cards.py:10-17`）→ 泛化器不得读取。

**结论：当前 confirmatory curve 删除 X。X1 仅保留为 diagnostic「observed-trace constraint」，
不得命名为 canonical executable artifact；X2 属于未来前瞻性 write-path instrumentation。**

### 1.3 「机械泛化」的合法边界（若将来做 X2）

每个签名位必须带可机器验证的证书：参数化需该槽在不同实例中实际变化或 schema 已声明 typed placeholder；
数据依赖需明确 producer→consumer 数据流或顺序干预证据；分支需两侧均被实际覆盖（未覆盖记 UNKNOWN）；
**单条轨迹未出现某步骤只能记 UNKNOWN，不能推出 ABSENT**；仅观察到固定顺序不能推出偏序。

LLM 边界：可做不进入 canonical hash 的命名/注释/角色显示名，可提出结构候选（须过冻结的确定性 verifier）；
**不得决定 polarity、方向、写目标角色、required/optional、branch、dependency edge**。
「temperature=0」不等于机械合法。必须记录 `trace_hash + initial_state_hash + tool/schema/policy version + generalizer_hash`。

## 2. 为什么执行式验证（原路线 D）不能单独得到 P

三个代码级反例（第二轮裁决）：

1. **不同签名、相同终态**：P1 的 J1 与 J2 签名不同（J2 多一次 policy READ，`program_dsl.py:104` 明确写入 signature），
   但当 policy 表的 θ 与 J1 的 θ 相同时，对业务表的最终状态完全相同 → 只比 final snapshot 看不见。
2. **相同签名、不同终态**：θ 不属于等价类（`program_dsl.py:10-16`），两个 P=1 实例可有不同 θ，
   在同一具体状态上走不同 branch → `P=1 ⇏ T_zx(s) = T_zm(s)`。
3. **偏序 ≠ 终态语义**：不同依赖边在无故障确定性执行下可产生相同数据库；要识别
   archive-before-delete 这类边，**必须注入 archive failure / 中断**。

另已核实：四种 near-miss 本身都是**完全可执行、且到达自己合法终态**的程序
（`generate_families.py:336` `"<=" if near_miss else prm["op"]`、`:587` 方向反转、`:828/:862` 门控子集、P4 跳过 archive），
所以"跑一跑看崩不崩"零判别力。

**因此**：certified P 的闭合路径是 `保留可执行规范 → canonical signature 比较`，
差分 witness 的作用降为（i）验证规范与实现一致、（ii）为 P=0 提供人可审计的反例、（iii）检测 stale policy/漂移。
若无法完成完备性证明（宇宙闭包 / canonical quotient / 观察语义含 labeled trace / soundness / completeness /
可达性策略 / 调度量化 / 故障模型 / 非确定性 / 统一 observer / artifact conformance 共 11 项义务），
只能叫 `catalog-complete mutation suite` 或 `V_T`，**不得称 certified P**。

2. T-only 存在实质缺口：**Cert_T ≤ 0.80**；

## 6. PASS 之后的 confirmatory 设计（功效算术已冻结）

**簇单位**：family 是 cluster；archetype / near-miss 机制是 **stratum 不是 cluster**；
sibling、target、style、seed、同 family 内多个 pair 全是**簇内重复，不增加独立 n**。

**8 个单侧声明**（4 机制 × {A01 accept ≤0.10, A11 retain ≥0.50}），Bonferroni `δ = 0.05/8 = 0.00625`：

| families/机制 | A01 允许接受数 | A11 至少保留数 |
|---:|---:|---:|
| 49 | 0/49 | 34/49 |
| 60 | 0/60 | 41/60 |
| 80 | ≤1/80 | ≥52/80 |
| **100（推荐）** | **≤2/100** | **≥63/100** |
| 120 | ≤4/120 | ≥75/120 |

- 数学最低 49/机制但要求零误收，脆弱；**推荐固定 100/机制 = 400 families / 800 primary pairs**；
- **不允许看到 3 个 A01 误收后再加到 120**；
- 100/机制时若 singleton 全对，Bonferroni 后单侧 precision LCB ≈ 0.9505；出现一个错误即过不了 0.95 门。

**防 generator 自证（全部必须）**：family split 在 rendering 前完成；confirm 用与开发集**完全不共享实现的 renderer**；
certifier 与接口规则在 confirm renderer 生成前 hash；confirm renderer 由**未写 certifier 的人**实现；
第五/第六 mutation 在 certifier hash 后由**独立 challenger** 选择（含 P=1 正控）；
challenge 失败**不得用四机制结果 pooled rescue**。否则只认证了 generator self-consistency。

**进入当前论文 main section 的最低门**：合法接口 ΔCert ≥ 0.20（family-cluster 95% LB > 0）；
final Cert ≥ 0.80（逐机制）；certified singleton 在有限 DSL 上 0 逻辑错误；经验 certifier 单侧 95% precision LCB ≥ 0.95；
lawful source availability ≥ 0.80（整体及逐机制）；**0 条 oracle-derived X/W**；独立 renderer/challenger collision set。

**独立成篇**（第二 DSL / 真实 workflow system / 真实 write-time artifact pipeline）当前 **NO_GO**。

## 7. 台账更正清单（第一轮裁决第 4 节，须一并落地）

1. 删除"29.5% 符号化 = P 不可识别下界"——θ 是 instance parameter，`program_dsl.py:10-16` 明确排除出等价类；
   当前 640 个完整 O 全部唯一、同 O 反 P 为 0 组，故经验 Bayes 下界 = 0；

4. P̂ v1 应表述为"**未迁移到未见 flip mechanism**"，而非"已被证明只是指纹"；
5. 删除"全部发现都被部署 P 卡死"的过度框定——coverage/H3、保留 decision+finish、压缩策略三条部署结论
   **不要求在线知道 P**；被卡的是 P×S 机制分解与逐候选 admission；
6. 「真实部署任务语言都是隐式的」收窄为：CausalMemBench 上的 text-only P̂ 是 **explicit-policy、单 generator
